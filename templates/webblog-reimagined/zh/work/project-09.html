ClassBridge Product Suite

一个项目体系，三个独立产品：ClassBridge Kids、IELTS Speaking Coach 与 Cantonese Speaking Coach。它们共享工程平台，但拥有不同用户、学习流程和数据边界。

01章节

共享代码不等于共享产品

Product Boundaries

ClassBridge 采用“共享平台 + 独立产品上下文”的结构。三个产品可以在同一个 macOS App 中切换，也复用同一套 Cloud Gateway 和 Admin Web，但每次请求都携带明确的产品身份。

产品选择会同时决定导航、可见内容、账号授权、调用额度、模型配置、用量日志和业务数据。Kids 的学习进度不会进入 IELTS 报告，IELTS 题库不会出现在粤语课程中。

01 / classbridge_kids
ClassBridge Kids
准备进入美国学校的儿童
围绕年级、校园场景、学科词汇、复习和口语建立分级学习闭环。
02 / ielts_speaking
IELTS Speaking Coach
成人 IELTS 口语备考者
按 Part 1 / 2 / 3 组织录音、转写、AI 反馈、历史洞察和模拟练习。
03 / cantonese_speaking
Cantonese Speaking Coach
普通话或英语背景的粤语学习者
以标准音、粤拼、跟读录音、ASR 对照和实用表达反馈训练粤语听说。

02章节

面向儿童适应新学校环境的分级英语产品

Product 01 · Kids
01
ClassBridge Kids
app_id = classbridge_kids

Kids 不是通用背词工具，而是把日常对话、课堂用语、学科内容和语音练习放进年级化学习池。首页根据当前等级、待复习内容和已掌握状态决定下一步入口。

学习引擎通过多轮练习、错题追加和复习日程维护掌握度；标准发音、录音测评、查词和 AI 问答由云端能力支持，正式试用模式不会用本地规则答案伪装成功。

按年级组织日常场景与学科内容
多轮学习、错题重试与到期复习
标准发音、录音测评与词级诊断
学习进度、掌握状态与 AI 问答
03章节

把完整口语流程做成可重复训练的工作台

Product 02 · IELTS
02
IELTS Speaking Coach
app_id = ielts_speaking

IELTS 产品围绕 Part 1、Part 2 和 Part 3 建立独立题库与练习状态。原生录音、实时波形、Part 2 准备与作答计时、题目语音、ASR 转写和报告生成形成连续闭环。

结构化题库按 120 套主题组织 1,200 道题，支持单 Part 训练、整组练习和模考规划。反馈围绕流利与连贯、词汇、语法和发音四个维度，并明确标记为 AI estimated band，而非官方成绩。

Part 1 / 2 / 3 题库与主题套题
原生录音、波形、计时与自动提交
ASR、四维反馈与中英文报告
历史筛选、趋势洞察与模考规划
04章节

从听标准音到录音反馈的实用粤语训练

Product 03 · Cantonese
03
Cantonese Speaking Coach
app_id = cantonese_speaking

粤语产品按模块、课程和字词句组织内容，同时展示繁体文本、粤拼和释义。学习者先听粤语标准音，再录音提交，系统依次完成 ASR 转写、目标文本对照和 AI 参考反馈。

反馈报告保留 transcript、疑似问题、自然度建议和下一步练习任务，历史记录可回看。产品聚焦实用跟读与表达，不把当前模型能力包装成精确的六声、声母、韵母或懒音客观评分。

模块、课程、字词句与粤拼内容
粤语标准音播放与跟读录音
ASR transcript 对照与 AI 参考反馈
历史报告、疑似问题与练习建议
能力边界：当前反馈用于辅助学习，不宣称提供粤语六声或声韵母的客观精确评分。
05章节

复用基础设施，把差异留在产品层

Shared Platform

SwiftUI App 提供原生桌面交互和产品切换，FastAPI Gateway 统一处理账号、内容发布、TTS、ASR、AI、额度和用量，React Admin Web 管理用户、内容、模型 Profile 与运营配置。

共享服务只负责通用能力。Kids 学习会话、IELTS 题库与报告、粤语课程与反馈分别进入独立领域接口和数据表，避免以大量条件分支把三个业务流程硬塞进同一模型。

01 / CLIENT
原生产品上下文
产品选择器决定当前导航、工作台、账号和 API 路由。
02 / IDENTITY
显式 App ID
请求携带产品 ID 与版本，令牌和会员关系绑定具体产品。
03 / GATEWAY
共享能力路由
Gateway 按产品选择模型 Profile、Prompt、额度和功能开关。
04 / DOMAIN
独立业务数据
学习进度、题库、课程、报告和状态机保持产品级隔离。
06章节

一个后台可以运营三种产品，但不能混淆三种用户体验

Isolation & Operations

多产品设计覆盖客户端、接口、数据和运营四层。管理端可以统一查看系统健康与成本，但内容审核、模型策略、用户授权和报告质量仍按产品筛选和配置。

01
导航隔离
切换产品后只显示对应学习入口和工作台。
02
账号与令牌
会员关系和访问令牌绑定 app_id，不能跨产品复用权限。
03
内容与进度
学习内容、题库、课程和进度采用各自的数据语义。
04
模型与 Prompt
每个产品配置独立模型 Profile、反馈政策和功能开关。
05
额度与成本
TTS、ASR、AI 和报告调用按产品记录额度与用量。
06
内容运营
Admin Web 按产品管理发布、审核、用户和报告质量。
